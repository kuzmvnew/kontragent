# ROADMAP — Kontragent

Последнее обновление: 15.09.2026

## Цель проекта

Создать сервис проверки юридических лиц и ИП в России.

Основной принцип продукта:

официальные данные
→ нормализация
→ конкретные факты и проверки
→ понятные риски
→ полезная карточка компании
→ публичный продукт
→ SEO-трафик
→ монетизация

---

# Основные правила

1. Двигаемся по фазам последовательно.
2. Не начинаем новую крупную фазу без фиксации результата предыдущей.
3. Допускается заранее строить технический фундамент следующих фаз, если это необходимо текущей фазе.
4. Не повторяем уже завершенную работу.
5. После крупных изменений обязательно запускаем тесты.
6. Актуальный код хранится в GitHub:
   kuzmvnew/kontragent
7. Текущее состояние проекта хранится в:
   PROJECT_STATUS.md
8. Этот файл является основным roadmap проекта.
9. Существенно менять порядок или содержание фаз без отдельного решения Михаила нельзя.

# ФАЗА 2 — MASTER REGISTRY

Статус: ✅ ЗАВЕРШЕНА

## Цель

Создать единый внутренний реестр компаний и ИП, к которому будут привязываться все внешние источники.

## Включает

- юридические лица
- индивидуальные предприниматели
- ИНН как основной идентификатор
- разделение 10-значных и 12-значных ИНН
- связь данных внешних источников с master registry
- базовое хранение сущностей

## Критерий завершения

Любой подключаемый официальный источник можно связать с существующей компанией или ИП в master registry.

# ФАЗА 3 — ОФИЦИАЛЬНЫЕ ИСТОЧНИКИ ДАННЫХ

Статус: 🟡 АКТИВНАЯ ФАЗА

## Цель

Подключить основной набор бесплатных и официальных источников, необходимых для полезной проверки контрагента.

## Уже сделано

- импорт данных ФНС по налоговой задолженности
- хранение снимков задолженности
- детализация задолженности
- импорт ФНС по доходам и расходам
- ingestion-механизмы
- базовая привязка источников к master registry

## Продолжаем

Подключать источники, необходимые для полноценной карточки компании и проверок.

Для каждого источника должны быть определены:

- официальный источник
- способ получения
- дата актуальности
- структура исходных данных
- ingestion
- нормализация
- связь с компанией
- обработка отсутствующих данных
- тесты
- отображение пользователю, если данные полезны

## Критерий завершения фазы

Подключён основной согласованный набор официальных источников, необходимый для первой полноценной версии карточки компании.

После завершения этой фазы открыть новый чат проекта.

Рекомендуемое название:

04 — Нормализация и качество данных

# ФАЗА 4 — НОРМАЛИЗАЦИЯ И КАЧЕСТВО ДАННЫХ

Статус: 🟡 ФУНДАМЕНТ УЖЕ ЧАСТИЧНО СОЗДАН

## Цель

Сделать данные из разных источников единообразными, проверяемыми и объяснимыми.

## Уже создан фундамент

- dataset registry contracts
- evidence contracts
- coverage contracts
- логика наличия и отсутствия данных
- работа с датами актуальности источников

## Нужно довести

Для каждого набора данных должно быть понятно:

- откуда данные
- за какой период
- насколько свежие
- есть ли покрытие конкретной компании
- означает ли отсутствие записи отсутствие события
- можно ли использовать данные для проверки
- какие ограничения имеет источник

## Критерий завершения

Все основные источники имеют единый понятный контракт качества, покрытия и происхождения данных.

---

# ФАЗА 5 — ПРОВЕРКИ И ЛОГИКА РИСКОВ

Статус: 🟡 ФУНДАМЕНТ ЧАСТИЧНО СОЗДАН

## Цель

Превратить сырые официальные данные в понятные пользователю проверки.

## Уже создан фундамент

- standardized tax check contracts
- regulatory requirement contracts
- permission checks
- section assessment contracts
- company assessment contracts

## Основной принцип

Не показывать пользователю просто массив государственных данных.

Сервис должен объяснять:

- что найдено
- почему это важно
- является ли это риском
- насколько свежие данные
- какой источник использован
- что именно пользователь должен проверить

## Важно

Не вводить единый общий "индекс надежности" компании как одну итоговую цифру без отдельного решения.

Сначала строим прозрачные и объяснимые проверки.

## Критерий завершения

Основные данные компании преобразуются в стабильный набор проверок, фактов, предупреждений и объяснений.

# ФАЗА 6 — ПОЛНАЯ КАРТОЧКА КОМПАНИИ

Статус: 🟡 УЖЕ НАЧАТА

## Цель

Собрать все полезные данные и проверки в одном понятном интерфейсе.

## Уже сделано частично

- company aggregator
- шаблон company.html
- сервис доходов и расходов
- вывод части финансовых данных
- partial templates

## Карточка должна отвечать на вопросы

- кто эта компания
- действует ли она
- кто руководитель и владельцы
- какие регистрационные данные
- финансовое состояние
- задолженности
- налоговые данные
- судебные и иные риски после подключения источников
- какие проверки требуют внимания
- откуда получены данные
- когда они обновлены

## Принцип интерфейса

Меньше необработанных данных.

Больше:

- выводов
- фактов
- акцентов
- предупреждений
- источников
- понятных пояснений

## Критерий завершения

По ИНН пользователь получает полноценную полезную карточку, которую уже имеет смысл использовать для реальной проверки контрагента.

# ПРАВИЛО СМЕНЫ ЧАТОВ

Не создавать новый чат после каждой маленькой задачи.

Новый чат внутри ChatGPT Project создаётся:

- после завершения крупной фазы;
- если текущий чат стал чрезмерно большим и медленным;
- если начинается крупная самостоятельная область проекта.

ChatGPT должен сам сообщать Михаилу, когда рекомендуется открыть новый чат.

При переходе в новый чат источниками истины являются:

1. ROADMAP.md
2. PROJECT_STATUS.md
3. актуальный GitHub
4. контекст ChatGPT Project

Не требуется вручную переносить всю историю старого чата.
