## Исходная ошибка

На main `925ef653dea638a70422aadace9993669ccdde16` локальная приёмка остановилась на извлечении ИНН. Причина: официальный XML 4.04 содержит получателя в `СвЮЛ`/`СвФЛ`, несколько фактов в `СвПредПод`, ИНН выдавшей поддержку организации на `СвПредПод`, дату решения в `ДатаПрин`. Предыдущие плоские fixtures не доказывали совместимость с bulk-выгрузкой.

PR #28 исправляет разбор без рекурсивного поиска ИНН и без fuzzy matching. Каждый факт получает ключ с ИНН выдавшей организации, ИдДок, НомерПод и ИНН получателя. NPD-only физлица учитываются, но не сохраняются в Company. Новых миграций нет: head `f7b2d8a4c1e3`.

## Контроль полноты вместо ненадёжного счётчика заголовка

Независимый probe `35110821029` выявил в трёх целых XML августовской выгрузки `КолДок=1` при 233/241/235 документах. CRC и XML EOF совпали. Это не успешная проверка КолДок и не доказательство полноты всего внутреннего реестра ФНС.

Теперь перед импортом выполняется независимый проход по ВСЕМ членам скачанного ZIP:

- SHA-256 сверяется с сохранённым свидетельством скачивания; после импорта проверяется повторно.
- ZIP читается по полному списку членов; повторяющиеся имена не допускаются.
- Каждый член прочитан до конца с проверкой CRC; каждый XML прочитан до корректного окончания.
- Отдельный структурный счётчик, не вызывающий normalizer, считает документы, факты, eligible ЮЛ/ИП и исключённые NPD-факты.
- Normalizer сверяется с независимыми числами по каждому файлу и архиву в целом.
- PostgreSQL reread должен совпасть с числом eligible фактов.
- Неизвестное расхождение КолДок, повреждение, пропущенный факт или дубликат сохраняемого ключа блокирует публикацию. Дубликаты не пропускаются молча.

Только известный профиль `ВерсФорм=4.04`, `ТипИнф=РЕЕСТРМСП-ПП`, `КолДок=1`, actual documents>1 допускает отдельное предупреждение `header_count_check=MISMATCH`. Это значение НЕ превращается в PASS. Сохраняются количество проблемных файлов и примеры; независимый manifest с SHA-256 пишется рядом с ZIP в `*.zip.integrity.json`.

Граница доказательства: полностью обработан конкретный опубликованный архив ФНС. Полнота внутренней базы ФНС не заявляется. `not_found` относится только к точному ИНН в этом датированном архиве.

Дата снимка берётся из `Документ/@ДатаСост`; дата актуальности metadata сохраняется отдельно как `metadata_data_date`. Дата получения и дата публикации не подменяют дату сведений.
