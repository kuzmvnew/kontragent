# SEO MVP — отбор первых 10 000 карточек компаний

Статус: planning / не влияет на текущую Phase 4

## Цель

Выбрать первые 10 000 публичных карточек Next Profile не по размеру компании и не по общей известности бренда, а по подтверждённому поисковому спросу на информацию о конкретном юридическом лице.

Ключевой принцип:

> Приоритет получает компания, которую люди ищут именно для идентификации, проверки, оценки надежности, рисков, реквизитов, руководства, финансов, судов, долгов, отзывов и контактов.

Запросы вида `тинькофф`, `ozon`, `wildberries`, `сбербанк` сами по себе не считаются сильным сигналом: их интент часто навигационный/consumer, а не проверка контрагента.

## 1. Исходный пул

Источник кандидатов — действующие юридические лица из Master Registry.

ИП в первый SEO-релиз включаются отдельным решением. По умолчанию MVP-10k строится вокруг ЮЛ.

## 2. Антинавигационный фильтр

### 2.1 Top-1000 по выручке

Компании, входящие в Top-1000 РФ по выручке, помечаются `enterprise_navigation_risk = true`.

Это не означает автоматическое исключение карточки из сайта. Это означает, что общий брендовый спрос не используется как главный аргумент для включения в первые 10 000.

### 2.2 Consumer brands

Отдельно маркируются компании/бренды с выраженным пользовательским навигационным интентом: банки, маркетплейсы, авиакомпании, массовый ритейл, телеком, крупные экосистемы и т. п.

Для них запрос `бренд` получает очень малый вес или ноль.

### 2.3 High-intent override

Даже компания из Top-1000/consumer может попасть в SEO-10k, если у нее подтвержден большой именно company-intelligence кластер: ИНН, реквизиты, проверить, надежность, риски, суды, долги, банкротство, учредители, директор и т. д.

## 4. Семантические кластеры

Полный словарь ведется отдельно в `config/seo/company_intent_clusters.yml`.

Основные группы:

1. идентификация — ИНН, ОГРН, КПП, полное/краткое название;
2. проверка — проверить компанию, проверить контрагента, проверка организации;
3. надежность — надежность, надежная ли компания, можно ли работать;
4. риски — риски компании, признаки риска, проблемная компания;
5. отзывы/репутация — отзывы, мошенники, обман, репутация;
6. реквизиты — реквизиты, банковские реквизиты, юридический адрес;
7. контакты — контакты, телефон, email, сайт, адрес;
8. руководство — директор, гендиректор, руководитель;
9. собственники — учредители, владельцы, бенефициары;
10. связи — связанные/аффилированные компании, связи директора;
11. финансы — выручка, прибыль, убыток, баланс, оборот;
12. долги — задолженность, налоги, приставы;
13. суды — арбитраж, судебные дела, иски;
14. ФССП — исполнительные производства, приставы;
15. банкротство — банкрот, процедура банкротства;
16. налоги — налоговая задолженность, налоговый режим;
17. лицензии/разрешения;
18. госзакупки/госконтракты;
19. РНП / недобросовестный поставщик;
20. статус — действующая, ликвидация, закрыта;
21. история — дата регистрации, возраст компании;
22. персонал — сотрудники, численность;
23. вакансии/работодатель;
24. санкции/комплаенс;
25. договор/сотрудничество — стоит ли работать, можно ли заключать договор.

## 5. Источники спроса

### Wordstat API — основной источник фактического спроса

Использовать официальный Wordstat API Yandex Cloud.

Нужно собирать:

- популярность запросов;
- связанные запросы;
- региональное распределение;
- динамику;
- вариации названия/ИНН.

Для MVP сначала достаточно общероссийского спроса + отдельного сигнала по крупнейшим регионам.

### Keys.so — конкурентный и SERP слой

Использовать API Keys.so для:

- ключей страниц конкурентов;
- запросов конкретных страниц Rusprofile / Checko / РБК Компании / List-Org и других;
- позиций в Яндексе;
- конкурентных URL;
- поиска дополнительных long-tail формулировок;
- проверки, какие страницы уже доказанно собирают SEO-трафик.

Данные Keys.so не заменяют Wordstat; они дают конкурентную и SERP-валидацию.

## 7. Intent Ratio

`intent_ratio` показывает, какая доля спроса относится к изучению/проверке компании, а не к навигации к ее продукту.

Концептуально:

`intent_ratio = company_intelligence_demand / max(total_observed_demand, 1)`

Не использовать его в одиночку: маленькая компания может иметь высокий ratio на очень малом абсолютном спросе.

## 8. SEO Priority Score

Первая версия должна быть объяснимой и версионируемой.

Пример логики:

- очень высокий вес: `проверить`, `надежность`, `риски`, `ИНН`, `ОГРН`, `реквизиты`, `суды`, `долги`, `банкротство`, `РНП`, `учредители`, `директор`;
- высокий: `отзывы`, `контакты`, `телефон`, `адрес`, `выручка`, `прибыль`, `лицензии`, `госконтракты`;
- средний: точное юридическое название;
- низкий: общий брендовый запрос;
- почти нулевой: брендовый запрос крупной consumer-компании без company-intelligence модификатора.

Концептуальная формула:

`seo_priority = weighted_intent_demand * intent_quality * competitor_signal * card_completeness * navigation_penalty`

Где `navigation_penalty` <= 1 и резко снижает влияние навигационных брендов.

Точные коэффициенты утверждаются после пилота на 500–1000 компаниях.

## 9. Card completeness gate

Высокий спрос сам по себе недостаточен. Карточка допускается в индекс только если она полезна и достаточно наполнена.

Минимальная версия gate должна проверять:

- идентификационные данные;
- статус;
- руководителя/учредителей, если источник позволяет публиковать;
- ключевые финансовые данные, если доступны;
- проверки/факты из подключенных источников;
- даты актуальности;
- источники;
- отсутствие запрещенных к публикации персональных/чувствительных данных;
- отсутствие технических ошибок/пустых блоков.

Порог completeness задается после аудита Phase 6/7.

## 10. Первый эксперимент

До массового расчета 10 000:

1. взять 500–1000 кандидатов из разных отраслей и регионов;
2. исключить/понизить Top-1000 по выручке и consumer-навигацию;
3. собрать Wordstat и Keys.so;
4. вручную проверить top-100 результата;
5. откалибровать веса;
6. зафиксировать `score_version = v1`;
7. рассчитать полный пул;
8. выбрать первые 10 000 по score + completeness gate.

## 11. Что НЕ делать

- не ранжировать компании по одной частотности названия;
- не считать популярность бренда эквивалентом спроса на проверку;
- не публиковать все миллионы страниц сразу;
- не создавать пустые/тонкие страницы ради количества URL;
- не индексировать страницы, не прошедшие completeness/privacy/security gates;
- не менять текущий порядок фаз: массовая SEO-публикация только после Security & Resilience Gate согласно ROADMAP.
