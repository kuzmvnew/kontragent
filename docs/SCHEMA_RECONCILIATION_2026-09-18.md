## Repair and ownership

The new revision contains frozen SQLAlchemy table definitions independent of
the evolving ORM. It creates the two missing tables with all required fields,
`BIGINT GENERATED BY DEFAULT AS IDENTITY` keys, cascading foreign keys to
`companies` and `data_sets`, named composite unique constraints, four tax-regime
indexes and five revenue/expense indexes. Revenue, expenses and profit/loss use
`NUMERIC(22, 2)`; tax regime codes use JSON; timestamps use time zones and
`now()` defaults. Client-side defaults remain client-side.

Before any DDL, it checks every pre-existing target table against the frozen
contract. Compatible tables receive no CREATE, ALTER, DROP, index creation,
comment change or data write. Incompatible columns, types, nullability, defaults,
identity, PK/FK/unique/index requirements or extra restrictive constraints raise
an explicit error containing the table, field and expected/actual difference.
The mixed missing/incompatible case fails before creating the missing table.

Only newly created tables receive the comment:

`created_by_alembic_reconciliation:c0c90245de4b`

Downgrade drops a target table only when its comment contains this exact marker
as a complete line. A null comment, legacy comment or another revision's marker
does not grant ownership. Existing migrations were not rewritten, and no
`alembic stamp`, `Base.metadata.create_all` or service-level workaround was used.

## Prevention and local checks

`scripts/check_schema_completeness.py` imports the registered ORM models,
inspects the live database in a read-only transaction and returns exit 1 for
missing tables/columns or incompatible required schema. It checks type details,
nullability, identity, defaults, PK, FK including actions, named unique
constraints and index definitions. Equivalent default/unique representations
and additional indexes are reported as observations. It performs no fixes.

CI now runs `uv run python scripts/check_schema_completeness.py` immediately
after `alembic upgrade head`, before pytest. This makes missing model migrations
fail during clean provisioning. `tests/conftest.py` also rejects a DATABASE_URL
targeting historical `kontragent` before test collection.

scan, fresh Alembic install, schema gate, round-trip and full isolated tests PASS.
