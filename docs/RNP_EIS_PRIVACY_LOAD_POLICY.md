# RNP / EIS — Privacy and Load Policy

Дата фиксации: 15.09.2026

Этот документ фиксирует продуктовые и технические ограничения для источника №12 `РНП / ЕИС`.

## 1. Публичные персональные данные

Персональные данные из записей РНП не публикуются в публичной карточке компании, публичном API, SEO-страницах, выгрузках и поисковом индексе.

Не выводить публично сведения о физических лицах, полученные из РНП, включая ФИО, персональный ИНН и иные идентификаторы/контактные или адресные сведения.

Для публичного продукта допускаются только сведения на уровне организации/записи РНП, необходимые для проверки контрагента: факт наличия записи, номер записи, контур/закон, даты включения/исключения, статус, основание, источник и дата данных — при условии, что они не раскрывают персональные данные физлица.

Если персональные поля не нужны для строгого matching организации, они не должны сохраняться в нормализованной продуктовой модели. Если технически необходимы для внутренней обработки конкретного типа записи, хранить минимально необходимый объём, не выводить его наружу и не писать в обычные application logs.

## 2. Matching

Связь с Master Registry выполняется только по устойчивым официальным идентификаторам организации/ИП, когда они присутствуют в записи: ИНН, ОГРН/ОГРНИП.

Название и ФИО не используются как автоматический ключ связи.

## 3. Нагрузка на ЕИС

До появления явных официальных лимитов используем консервативный режим LOW LOAD.

Базовые настройки:

- один сетевой worker;
- не более одного активного запроса к ЕИС одновременно;
- минимальный интервал между SOAP-запросами — 30 секунд;
- скачанный архив кэшируется локально и повторно не запрашивается без причины;
- уже обработанные период/регион/version пропускаются;
- на HTTP 429/403, SOAP rate-limit или аналогичную защитную ошибку — немедленная остановка текущего цикла, без агрессивных повторов;
- на временные 5xx/network ошибки — exponential backoff 60 / 120 / 300 секунд, затем остановка;
- массовый исторический backfill выполняется медленно, очередью, преимущественно вне интерактивного пользовательского запроса;
- пользовательская карточка никогда не должна запускать прямой массовый crawl ЕИС.

Если официальная документация/ответ ЕИС укажет более строгие лимиты, настройки автоматически должны быть ужесточены. Если будут опубликованы более высокие допустимые лимиты, повышать нагрузку можно только отдельным решением после успешной длительной эксплуатации LOW LOAD.

## 4. Credential safety

Токен доступа хранится только локально/в secret storage, не публикуется в GitHub, чатах, логах, UI и API.

## 5. Семантика отсутствия

Ошибка доступа, блокировка, rate limit, отсутствие credential или недоступность ЕИС всегда дают `unavailable`, а не `not_found`.

`not_found` допустим только при успешной проверке в подтверждённом покрытии данных.
