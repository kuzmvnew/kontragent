# SOURCE PASSPORT — РНП / ГИС ЕИС ЗАКУПКИ

Дата фиксации: 15.09.2026
Статус: официальный машинный доступ подтверждён; ожидается регистрация получателя машиночитаемых данных и live smoke-test.

## 1. Источник

- Система: ГИС ЕИС ЗАКУПКИ.
- Официальный сайт: https://zakupki.gov.ru/
- Оператор ЕИС: Федеральное казначейство.
- Реестр: Реестр недобросовестных поставщиков (подрядчиков, исполнителей), прежде всего РНП по 44-ФЗ; после live-подтверждения 44-ФЗ отдельно проверяется РНП по 223-ФЗ.
- Source Registry code: `eis`.

## 2. Правовое и техническое основание доступа

С 01.01.2025 прежний FTP-канал ЕИС не является рабочим способом получения машиночитаемых данных.

Постановление Правительства РФ от 09.12.2024 № 1740 изменило Положение о ЕИС, утверждённое постановлением Правительства РФ от 27.01.2022 № 60. Для получения информации и документов, размещённых в форме открытых данных в машиночитаемом виде, требуется идентификация, аутентификация и авторизация в ЕИС.

Официальные сервисы отдачи:

- `getDocsIP` — для физических лиц;
- `getDocsLE` — для юридических лиц.

Для работы требуется регистрация получателя машиночитаемых данных с использованием ЕСИА.

Официальная документация ЕИС:

- раздел документов: https://zakupki.gov.ru/epz/main/public/document/view.html?searchString=&sectionId=432&strictEqual=false
- инструкция по сервисам отдачи: https://zakupki.gov.ru/epz/main/public/download/downloadDocument.html?id=41500

## 3. Выбранный режим для проекта

Режим: **AUTHENTICATED OFFICIAL SOAP / DOCUMENT DELIVERY**.

На первом этапе используем `getDocsIP`, если доступ оформлен на физическое лицо. Для юридического лица архитектура должна позволять заменить transport/auth на `getDocsLE` без изменения доменной модели РНП.

Точка доступа физлица:

`https://int44.zakupki.gov.ru/eis-integration/services/getDocsIP`

Namespace SOAP:

`http://zakupki.gov.ru/fz44/get-docs-ip/ws`

Для РНП по 44-ФЗ подтверждается целевой subsystem `RNP`. В интеграционных примерах текущего сервиса для массового запроса по региону/дате используется документ `unfairSupplier2022`. Точный действующий контракт полей и XML внутри возвращаемого архива фиксируем только после live smoke-test с нашим токеном и фактическим XSD/ответом ЕИС.

## 4. Почему не используем другие способы

Не использовать:

- закрытый с 01.01.2025 FTP ЕИС;
- scraping HTML-поиска РНП;
- обход anti-bot/ограничений сайта;
- сторонний платный API как источник истины.

Публичная HTML-часть остаётся полезной для ручной проверки, но не является нашим рабочим ingestion-каналом.

## 5. Секреты и безопасность

Токен `getDocsIP` хранится только локально:

`EIS_IP_TOKEN=<token>`

`.env` уже исключён из Git через `.gitignore`.

Запрещено:

- коммитить token в GitHub;
- печатать token в логах;
- сохранять token в ingestion details;
- передавать token в URL query string;
- прикреплять `.env` в чат или issue/PR.

При скачивании сформированного архива токен также передаётся только в HTTP header, как требует сервис.

## 6. Product semantics

Наличие записи в РНП — самостоятельный существенный факт риска и должно показываться с:

- основанием включения;
- номером записи;
- законом/контуром (44-ФЗ / 223-ФЗ);
- датой включения;
- плановой/фактической датой исключения;
- текущим статусом записи;
- источником и датой данных.

Отсутствие записи можно трактовать только в рамках реально загруженного/проверенного покрытия ЕИС. Ошибка доступа, отсутствие токена, ошибка SOAP или недоступность ЕИС никогда не превращаются в `not_found`.

Связь с Master Registry — по ИНН/ОГРН/ОГРНИП из официальной записи. Название не используется как автоматический ключ.

## 7. Текущее решение по Phase 3

Источник №12 **не переносится в Wave 2 на основании ограничений доступа**, потому что официальный допустимый машинный канал существует.

Текущий blocker — не технический запрет, а обязательная регистрация получателя машиночитаемых данных и получение credential/token.

До получения token в коде допустимы:

- request builders;
- response parser;
- credential-safe provider;
- offline unit tests;
- probe CLI, который отказывается обращаться в сеть без token.

Полноценный ingestion/model не фиксируется до первого реального архива РНП и инспекции его XML.
