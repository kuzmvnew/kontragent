### Как ведём чек-лист во время разработки

Перед блоком работы: назвать фазу, цель, затрагиваемые файлы и ожидаемый результат. После блока: обновить этот файл по фактам и дать короткий итог Михаилу.

Различать четыре статуса: код создан → импорт подтверждён → результат показан в интерфейсе → проверено и сохранено. Не отмечать источник полностью готовым только по наличию обработчика или модели.

Формат итога каждого блока:

- Сделано: одно конкретное изменение и его польза пользователю.
- Файлы: созданные/изменённые пути.
- Проверка: команда и результат тестов, данные импорта или результат просмотра интерфейса; явно указать, что не проверялось.
- Сохранение: commit и подтверждение доступности в GitHub.
- Осталось: незавершённые пункты текущего блока.
- Далее: один ближайший шаг с понятным результатом.

Чек-лист обновляется в рамках рабочих сессий, не является фоновым мониторингом Mac или базы. Изменения, не отправленные в GitHub, проверяются по предоставленному выводу или отдельно доступному окружению. Обновление документа на GitHub само по себе не обновляет локальную папку на Mac.
