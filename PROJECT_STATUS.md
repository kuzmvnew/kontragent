## Текущий блок — источник №10: НПД ФНС

🟡 **Начат.** Source passport: `NPD_SOURCE_PASSPORT.md`.

Подтвержден официальный публичный сервис ФНС и официальный REST API проверки статуса НПД.

Режим использования: **`PUBLIC_LIVE / ON_DEMAND`**, не bulk.

Ключевое ограничение официального API: не чаще **2 запросов в минуту с одного IP**. Поэтому не строим массовый обход 4,7 млн ИП. Для текущего продукта:

- ЮЛ → `not_applicable`;
- ИП → точечная live-проверка по 12-значному ИНН и дате;
- будущий Person → тот же источник только при подтверждённом ИНН и privacy/source-passport правилах.

## Person

Person остаётся отдельным последующим продуктовым направлением и **не меняет текущий порядок Фазы 3 по компаниям**. Backlog и режимы доступа находятся в `PERSON_CHECK_SOURCES.md`.

До Privacy & Person Gate:

- не делать массовую SEO-индексацию физлиц;
- не публиковать избыточные персональные идентификаторы;
- не делать негативный вывод только по совпадению ФИО;
- учитывать expiry/purge источников;
- consent-only/document checks держать приватными.

## Важные продуктовые ограничения

- Не строить общий итоговый «индекс надёжности» как единственную истину без отдельного решения.
- Показывать факты, проверки, источники, даты, покрытие и объяснение результата.
- `unavailable`/ошибка источника нельзя превращать в «ничего не найдено».
- Отсутствие записи относится только к конкретному набору/дате/проверке.
- Новый источник не добавляется в обязательный scope Фазы 3 автоматически.
