### Новое продуктовое решение: Person / проверка физических лиц

15.09.2026 согласовано направление: после сильного ядра проверки компаний развивать Person так, чтобы по числу полезных критериев не отставать от ведущих российских сервисов.

В roadmap добавлены категории:

- PERSON CORE — идентификация, связи с ЮЛ/ИП, дисквалификация, НПД, ограничения участия, субсидиарная ответственность, наследственные дела;
- PERSON ENFORCEMENT — ФССП с категоризацией производств, отдельные алименты, налоговые взыскания, розыск, суды и банкротство;
- PERSON COMPLIANCE — терроризм/экстремизм, ОМУ, иностранные агенты, утрата доверия, запрет спортивных мероприятий, РПДЛ/PEP;
- PERSON ASSETS/IP/PROFESSIONAL — товарные знаки и патенты, залоги, профессиональные реестры;
- PERSON DOCUMENTS — приватные/on-demand проверки паспорта, образования, водительского удостоверения и договорные проверки при необходимом согласии.

Отдельно зафиксировано требование по ФССП: не показывать один общий показатель «долги». Хранить предмет исполнения и нормализовать как минимум алименты / налоги / кредиты и займы / штрафы / ЖКХ / ущерб / иное / не классифицировано. Алименты и налоговые взыскания должны иметь отдельные фильтры.

### Person: обязательное ограничение до реализации

🟡 Список источников и продуктовая архитектура согласованы, **но ни один новый Person-источник не считается реализованным только из-за добавления в roadmap**.

До production каждый источник проходит source-passport gate:

- способ официального получения;
- можно ли автоматизировать запросы;
- можно ли хранить/кэшировать;
- можно ли повторно публиковать;
- можно ли использовать в коммерческом продукте;
- срок публичности и правило expiry/purge;
- разрешённые идентификаторы и минимально необходимые поля;
- правила free UI / paid report / API / export.

Режимы источников: `OPEN_DATA / PUBLIC_LIVE / ON_DEMAND / LICENSED / CONSENT / EXCLUDE`.

Публичная web-страница государственного реестра сама по себе не считается разрешением на массовое зеркало и бессрочную перепубликацию.

До отдельного Privacy & Person Gate:

- не открывать массовую SEO-индексацию карточек физических лиц;
- не публиковать паспортные реквизиты, СНИЛС, точный домашний адрес и другие избыточные идентификаторы;
- не делать уверенный негативный вывод только по совпадению ФИО;
- не хранить публично навечно статус, который первоисточник обязан снять после окончания установленного срока;
- consent-only/document checks держать приватными.

### Как ведём чек-лист во время разработки

Перед блоком работы: назвать фазу, цель, затрагиваемые файлы и ожидаемый результат. После блока: обновить этот файл по фактам и дать короткий итог Михаилу.

Различать четыре статуса: код создан → импорт подтверждён → результат показан в интерфейсе → проверено и сохранено. Не отмечать источник полностью готовым только по наличию обработчика или модели.

Для Person добавляется пятый обязательный слой: **режим доступа/публикации подтверждён**. Написанный парсер не означает, что источник можно массово хранить, показывать бесплатно, продавать или отдавать через API.

Формат итога каждого блока:

- Сделано: одно конкретное изменение и его польза пользователю.
- Файлы: созданные/изменённые пути.
- Проверка: команда и результат тестов, данные импорта или результат просмотра интерфейса; явно указать, что не проверялось.
- Сохранение: commit и подтверждение доступности в GitHub.
- Осталось: незавершённые пункты текущего блока.
- Далее: один ближайший шаг с понятным результатом.

Чек-лист обновляется в рамках рабочих сессий, не является фоновым мониторингом Mac или базы. Изменения, не отправленные в GitHub, проверяются по предоставленному выводу или отдельно доступному окружению. Обновление документа на GitHub само по себе не обновляет локальную папку на Mac.

## Главная цель

Сервис проверки юридических лиц и ИП в России с последующим полноценным модулем проверки физических лиц Person.

Текущая последовательность не меняется: основной продукт по компаниям должен быть доведён до полезной карточки до того, как Person станет отдельным крупным фронтом разработки.

Логика продукта:

официальные данные
→ понятные факты и риски
→ полезная карточка компании / Person-проверка
→ SEO-трафик по допустимым страницам
→ реклама / первые продажи
→ платные данные и B2B SaaS
