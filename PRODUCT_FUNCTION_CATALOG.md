# PRODUCT FUNCTION CATALOG — Kontragent

Status: APPROVED BACKLOG / EXECUTION INPUT
Date: 2026-09-17

Каталог объединяет функции из проекта, наших обсуждений и реальных ТЗ заказчиков. Наличие функции в каталоге не означает, что она уже реализована. Фактический статус подтверждается кодом и `PROJECT_STATUS.md`.

## A. Company Core

- поиск по ИНН, ОГРН, названию и иным подтверждённым идентификаторам;
- полноценная карточка ЮЛ/ИП;
- реквизиты, статус, история регистрационных изменений;
- руководители, владельцы, связанные организации;
- Relationship Graph;
- финансовые данные и динамика;
- налоговые данные;
- контрольные мероприятия;
- лицензии и регуляторные разрешения;
- СРО;
- судебные данные;
- исполнительные производства;
- банкротство и сообщения о намерении;
- закупки и РНП при подтверждённом официальном доступе;
- залоги;
- товарные знаки / патенты / IP;
- транспортные и отраслевые реестры по Applicability;
- compliance-факты;
- доказательства, источник и дата для каждого вывода.

## B. Risk / Decision Layer

- Evidence -> Fact -> Signal -> Recommendation;
- Applicability по типу компании, отрасли и контексту сделки;
- Core и Context проверки;
- Derived Metrics;
- отдельные Risk и Coverage;
- hard rules для фактов, которые не должны размываться баллами;
- материальность сумм относительно выручки, активов, капитала и других корректных знаменателей;
- версионирование ruleset;
- Deal Context: роль, предмет сделки, сумма, аванс, территория, сроки;
- объяснимые рекомендации пользователю;
- внутренняя техническая оценка допускается для сортировки/фильтрации, но публичный единый индекс не является обязательным результатом v1.

## C. Summary / Report

- короткий Executive Summary;
- 3–5 главных факторов;
- что изменилось;
- что не удалось проверить;
- рекомендации;
- числа, периоды и формулы для количественных выводов;
- Public Summary;
- User Summary;
- Due Diligence Summary;
- Monitoring Summary;
- Bulk Summary;
- отдельный Person Summary;
- PDF-отчёт проверки;
- XLSX/табличный export;
- snapshot и версия методики в отчёте.

## D. Lists / Bulk Check

- создание произвольного количества списков в рамках тарифа/политики;
- загрузка XLSX/CSV;
- вставка ИНН/ОГРН;
- массовая проверка;
- фильтры по фактам, рискам, статусам и coverage;
- export результата;
- private/shared lists;
- permissions для общих списков;
- история массовой проверки.

## E. Monitoring / Event Engine

- единая модель событий для всех источников;
- изменения регистрационного статуса;
- руководители / владельцы / адрес / капитал;
- налоги и отчётность;
- ФССП;
- суды;
- банкротство;
- лицензии / СРО;
- закупки / РНП;
- залоги;
- compliance;
- транспортные разрешения;
- positive events — исчезновение/закрытие риска;
- internal data-quality events;
- внутренняя лента;
- email;
- immediate / digest режимы;
- пользовательская настройка категорий уведомлений.

## F. Workspace v1

- организация-клиент;
- несколько пользователей;
- роли минимального уровня;
- private/shared lists;
- notes;
- история запросов;
- базовый audit trail;
- разделение пользовательских и административных функций.

Полный Enterprise IAM, SSO и сложные политики доступа не являются условием Workspace v1.

## G. Financial Intelligence

- баланс, ОФР и доступные формы ГИР БО;
- коэффициенты ликвидности, устойчивости и рентабельности;
- динамика выручки, прибыли, капитала, обязательств;
- аналитический баланс;
- финансовая нагрузка относительно бизнеса;
- отдельный Financial Distress Forecast;
- факт банкротства всегда отделён от прогноза;
- возможный operational overlay по данным ОФД/онлайн-ККТ только при правомерном доступе самой компании/клиента.

## H. Court Intelligence

- роль в деле;
- количество дел;
- активные требования;
- суммы требований и взысканий;
- `claims / revenue` и иные объяснимые коэффициенты;
- динамика судебной нагрузки;
- провал внутрь дела;
- инстанции, документы, требования, аргументы, доказательства, нормы права, исходы;
- в будущем — вероятностная модель исхода дела;
- прогноз исхода не является фактом и не становится hard blocker без отдельного подтверждённого события.

## I. Person Core — после Company B2B Core

- Person Registry;
- identity resolution;
- match_confidence;
- связи с ЮЛ/ИП;
- дисквалификация;
- НПД;
- банкротство;
- ФССП в допустимом режиме;
- публичные compliance-реестры;
- суды при допустимом режиме доступа;
- on-demand / consent-only документные проверки;
- запрет негативного уверенного вывода по одному ФИО;
- expiry/purge для ограниченных по сроку сведений.

## J. Compliance

- Росфинмониторинг: терроризм/экстремизм и ОМУ как отдельные признаки;
- иностранные агенты;
- утрата доверия;
- российские и позднее международные санкционные перечни;
- 50% / ownership rules при наличии достоверного графа владения;
- PEP/RPДЛ как отдельный поздний слой на официальных первоисточниках;
- связанные лица и бенефициары;
- FATF/offshore/no-information-exchange контекст при подтверждённой правовой модели;
- отдельный Compliance-модуль, а не один флаг в карточке.

## K. API / Enterprise

- внешний API;
- API keys и rate limits;
- audit log;
- SSO;
- SLA;
- интеграции клиента;
- formal support;
- команды и seats;
- биллинг/подписки;
- Enterprise security;
- готовность к требованиям госзакупок, если принято решение участвовать.

## L. Public / SEO / Marketing

- первые 10 000 максимально наполненных карточек компаний;
- SEO URL, title, description, H1/H2/H3, schema, sitemap, canonical, robots;
- внутренняя перелинковка;
- публичный projection только разрешённых данных;
- отдельные лендинги будущих продуктов;
- журнал/полезные статьи после запуска;
- боты/мини-приложения/контентные каналы как маркетинговый backlog после продукта.

## M. Обязательные Gates перед 10k SEO

1. Security & Resilience Gate.
2. Legal Launch Gate.
3. Product / Company Card Acceptance Gate.

Все три должны быть пройдены до массовой индексации.

## N. Что не должно задерживать первый коммерческий Company Core

- международное покрытие всех стран;
- мобильные приложения;
- полный legal-tech уровня «Мой арбитр»;
- предсказание судей/дел как обязательная функция MVP;
- большой Enterprise IAM;
- CRM/звонилка/Leads до готовности Company Core и Monitoring;
- публичная массовая база физических лиц.
