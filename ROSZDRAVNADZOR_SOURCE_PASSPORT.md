## Общая граница

W1-004 состоит из четырёх самостоятельных официальных каналов. Их статусы,
полнота и даты нельзя смешивать. Source of Truth — только Росздравнадзор.
Сопоставление с Company выполняется только по точному ИНН/ОГРН. Название,
адрес и сайт не являются доказательством связи.

Условия официальных открытых данных разрешают свободное, бесплатное,
бессрочное, в том числе коммерческое повторное использование при законной
цели, отсутствии искажения и сохранении ссылки на источник:
`https://roszdravnadzor.gov.ru/opendata`.

## A. Открытые реестры лицензий

Три официальных набора:

| Код | Вид деятельности | URL |
|---|---|---|
| `roszdrav_pharma_licenses` | Фармацевтическая деятельность | `https://roszdravnadzor.gov.ru/opendata/7710537160-ls_licenses` |
| `roszdrav_narcotics_licenses` | Оборот наркотических средств и психотропных веществ | `https://roszdravnadzor.gov.ru/opendata/7710537160-nark_licenses` |
| `roszdrav_medical_device_maintenance_licenses` | Техническое обслуживание медицинских изделий | `https://roszdravnadzor.gov.ru/opendata/7710537160-md_licenses` |

- Product use-case: показать отраслевые лицензии контрагента, их номера,
  даты, работы, места деятельности и опубликованные сведения о прекращении,
  приостановлении/возобновлении и аннулировании.
- Machine access: публичные ZIP с одним XML и опубликованная XSD.
- Режим: `BULK SNAPSHOT`.
- Exact identifiers: ИНН, ОГРН/ОГРНИП, номер лицензии.
- Обновление: история официальной страницы показывает недельные версии.
- Реальные файлы `data-20260913-structure-20210307.zip` проверены до кода:
  CRC/EOF PASS; по одному XML в архиве; 21 433 / 7 429 / 2 699 записей;
  пустых ИНН — 0; уникальных ИНН — 21 433 / 7 429 / 2 698.
- Аномалия metadata: дата изменения/имя файла — 13.09.2026, а официальная
  «дата актуальности» — 20.09.2026, то есть позже даты исследования.
  Обе даты должны храниться раздельно; будущая metadata-дата не подменяет
  фактическую дату файла.
- Хранение: полный текущий snapshot, raw payload, SHA-256, журнал ingestion.
- `found`: в полном успешно опубликованном snapshot найден exact-INN.
- `not_found`: exact-INN отсутствует во всех трёх полных snapshot выбранной
  даты. Это не доказывает отсутствие лицензий других видов и не определяет,
  нужна ли лицензия конкретной компании.
- `not_applicable`: только явная неприменимость сущности/проверки, а не
  отсутствие строки.
- `unavailable`: хотя бы один обязательный snapshot не загружен, повреждён
  или не прошёл проверку полноты; частичный набор не выдаётся за not_found.
- Coverage: exact-INN join каждой категории и объединения с Master Registry.

## B. Полный Единый реестр лицензий

- Официальный поиск: `https://roszdravnadzor.gov.ru/services/licenses`.
- Product use-case: точечная проверка всех опубликованных видов лицензий,
  включая виды, которых нет в трёх публичных bulk XML.
- Поиск поддерживает номер лицензии, ИНН, ОГРН и наименование; результаты
  можно выгрузить в XLS.
- Фактический transport страницы: `POST /ajax/services/licenses`, JSON.
  Это внутренний transport официального публичного сервиса, но не
  документированный публичный API.
- Полный набор открытых данных №5 доступен только после авторизации ЕСИА.
- Режим интеграции сейчас: `ON_DEMAND_WITH_DATED_CACHE`, один ИНН на явный
  запрос пользователя, без массового обхода Master Registry.
- Ограничения: публичные rate limits не опубликованы; форма содержит
  `i_am_human`. Использовать low-load, cache reuse, timeout/backoff и
  немедленно прекращать запросы при защитном ответе/captcha/rate-limit.
- Exact identifiers ответа: ИНН, ОГРН/ОГРНИП, номер лицензии.
- Реальный точечный запрос 16.09.2026 по ИНН `5260041417` вернул HTTP 200,
  JSON и 6 строк разных видов лицензий.
- `found`: официальный успешный ответ содержит хотя бы одну строку с exact-INN.
- `not_found`: официальный успешный exact-INN запрос вернул 0 строк.
- `unavailable`: transport/source/captcha/rate-limit/parse/identity error.
- Хранение: датированный cache ответа и ошибки; ошибка не становится not_found.
- Успешный cache текущего дня переиспользуется; повторный обычный запрос не
  обращается к источнику снова. Принудительное обновление доступно только
  явному acceptance/операционному вызову.
- Coverage: успешные cache-INN, error rows, checked/unchecked Master Registry.

## C. Государственный реестр медицинских изделий

- Официальный виджет: `https://elk.roszdravnadzor.gov.ru/widget/`.
- Публичный API виджета:
  `POST /public-gateway/registered-med-product/api/v1/med-product/filter-public`.
- Endpoint использует `Russian Trusted Root CA`, отсутствующий в стандартном
  bundle certifi/macOS. Клиент C добавляет только для фиксированного ELK-host
  репозиторный trust anchor, полученный по HTTPS-ссылке Госуслуг; сертификат
  self-signed, действует до 27.02.2032, SHA-256 fingerprint:
  `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`.
  TLS verification не отключается.
- Полный open-data dataset №11 доступен только после авторизации ЕСИА.
- Product use-case: lookup регистрационного статуса изделия по точному номеру
  регистрационного удостоверения/ЕРУЛ, а не автоматическое доказательство
  связи изделия с Company.
- Режим: `ON_DEMAND_WITH_DATED_CACHE` по регистрационному номеру.
- Реальный минимальный запрос 16.09.2026: HTTP 200, `totalElements=81263`.
- Ответы содержат номер РУ, статус, даты, название изделия, производителя,
  заявителя/представителя и адреса, но не ИНН/ОГРН этих организаций.
- Поэтому автоматическая связь с Company запрещена. Название и адрес не
  используются как evidence. Для Company exact-INN check — `not_applicable`
  с причиной `official_registry_has_no_company_exact_identifier`.
- `found`/`not_found` применяются только к отдельному lookup по точному номеру
  РУ. Ошибка источника — `unavailable`.
- Хранение: датированный cache lookup и raw official response.
- Успешный exact-number cache текущего дня переиспользуется; автоматических
  повторов после source/network error нет.
- Coverage Master Registry: N/A до появления официального exact identifier.

## D. Организации, имеющие право проводить клинические исследования

- Официальный набор:
  `https://roszdravnadzor.gov.ru/opendata/7710537160-organizations`.
- Machine access: публичный CSV.
- Режим: `BULK SNAPSHOT`.
- Exact identifier: ИНН.
- Реальный файл `data-20260906-structure-20191004.csv`: 295 записей,
  291 уникальный ИНН, пустых ИНН — 0; metadata изменена 06.09.2026,
  дата актуальности 13.09.2026.
- Product use-case: показать подтверждённое включение организации в перечень
  организаций, имеющих право проводить клинические исследования медизделий.
- `found`: exact-INN присутствует в полном snapshot.
- `not_found`: exact-INN отсутствует в полном успешно опубликованном snapshot
  на указанную дату; это не общая оценка медицинской деятельности.
- `unavailable`: snapshot отсутствует/неполон/невалиден.
- Coverage: exact-INN join snapshot с Master Registry.

## Карточка компании

Один блок «Росздравнадзор» показывает раздельно:

1. три категории открытых лицензий (A);
2. датированный результат полного поиска лицензий и кнопку точечной проверки (B);
3. честное ограничение C: изделия нельзя привязать к компании без exact ID;
4. статус в перечне клинических исследовательских организаций (D).

Отсутствие записи, непроверенность и ошибка всегда визуально различаются.
`auto_update=NOT_CONFIGURED`, пока отдельное расписание фактически не создано.
